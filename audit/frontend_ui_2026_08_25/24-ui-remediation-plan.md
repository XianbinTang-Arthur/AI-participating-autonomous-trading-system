# AATS 前端整改计划

> 状态：已实施；验收结果见 `25-ui-remediation-report.md`
> 基线：2026-08-25 / `e4954271427554aa4f56f1114827dc15b62932f1`

## 批次 1：P0 交易安全

1. 将“恢复自动运行”统一切换为需要二次确认的危险操作。
2. 确认文案必须明确：动作会尝试恢复自动交易；后端仍会再次校验恢复资格。
3. 保持审计 reason `ui_manual_resume` 和服务端权限/恢复门禁不变。

验收：取消确认时零请求；确认后仍只有一个 POST；回归测试锁定 `runDangerousAction`。

## 批次 2：P1 数据契约与中文语义

1. 补齐四个合约敞口风控码的中文映射，并与后端 operator reason 保持一致。
2. AI provider 与候选档位摘要只显示中文业务名；保留技术 ID 的专用明细不受影响。
3. RDP `blocking_flags` 复用现有 humanizer，不改审批门禁或原始数据库记录。

验收：真实页面不再出现 `risk / max / short / notional / exceeded`、`provider baseline_fallback`、摘要中的 `trend_aggressive` 或“active 参数不一致”。

## 批次 3：P2 响应式与信息架构

1. 主导航和策略/风险分区导航在窄屏改为单行横向滚动，活动路由自动进入可视区。
2. 1280px 保留多列工作区；通用 span 堆叠断点调整到 1100px。
3. 加入跳过导航链接与全局语义 H1。

验收：390px 主导航约 42–50px 高；1280px 主页不再因通用 span 规则翻倍增长；全路由仍无文档级横向溢出。

## 批次 4：P3 文案与一致性

1. 风险页敞口标题全中文化。
2. 回放页空态使用“多头/空头腿级差异”。
3. 不删除运维所需的决策 ID、订单 ID、策略 family ID 等审计标识。

## 批次 5：验证与报告

1. 运行目标单测、全部 unit、ruff；运行受影响 dashboard/auth 集成测试。
2. 提交后按标准入口重新部署本地模拟盘；提交前使用拒绝所有写方法的临时前端预览源连接现有 derivatives 后端，重跑 11 路由 × 6 尺寸。
3. 实测详情 dialog 的打开/Escape/焦点回收；验证 console、可见错误、空态、导航活动项。
4. 写入 `22-frontend-ui-audit.md`、`23-frontend-backend-contract-audit.md`、`25-ui-remediation-report.md`，明确残余未知项。

> 实施说明：本任务未获得创建 Git commit 的明确指令，因此没有为了视觉复核而提前提交或绕过部署规范。最终部署复验保留为提交后的上线门禁；当前浏览器证据只证明未提交前端工作区与现有模拟后端的组合行为。

## 非目标

- 不触发实盘 profile、不操作真实资金、不点击会提交交易/治理/账号变更的按钮。
- 不为降低页面高度而隐藏关键风控、恢复、对账或审计证据。
- 不引入 React/Vue 或新的构建链；本轮保持原生 ES Module 架构。
