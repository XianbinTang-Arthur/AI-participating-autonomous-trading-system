# 22 — AATS 全页面前端 UI/UX 审计

> 文档状态：现行最终审计结论
> 审计日期：2026-08-25
> 起始 Git：`e4954271427554aa4f56f1114827dc15b62932f1`；整改实现提交：`830e25114c7e8fd0eb4b278061336e440b786f88`
> 环境：`derivatives` 本地模拟后端；禁止从本文推断实盘、交易所或资金可用性

## 1. Overall Assessment

AATS Operator 控制台不是一个缺少结构的“空壳前端”。它已经具备成熟的两阶段 bundle、状态真相、错误/空态、权限、详情抽屉、移动记录卡和风险门禁表达。本轮的核心缺陷集中在四类：恢复自动运行缺少 UI 二次确认；新增后端枚举未完整本地化；1280px 通用栅格过早退化；横向和纵向导航在小屏占用过多空间。

整改保持原生 HTML/CSS/ES Module 架构，没有引入框架、构建链或虚假数据。修复后，66 个“11 路由 × 6 视口”组合全部到达已同步状态，没有文档级横向溢出、控件文字裁切、可见错误面板或遗留骨架；主导航保持 42px 单行，活动路由 66/66 可见。结论为“主要问题已实质整改”，但尚不能等同于生产发布验收，因为变更未提交/部署到 8001，真实读屏器、最终 console/HAR 和若干无数据业务分支仍需补测。

## 2. 审计方法与真实性边界

审计按以下顺序执行：

1. 读取 `view-router.js`、`store.js`、页面壳、共享组件、动作模块、全部视图模块和后端 bundle 分发器；
2. 建立路由、panel、endpoint、字段和操作清单；
3. 使用已登录的本地 derivatives 模拟栈渲染全部路由；
4. 在 1920、1440、1280、1024、768、390px 宽度采集 DOM、尺寸、溢出、活动路由、骨架和可见错误证据；
5. 冻结 P0–P3 问题矩阵后分批修复；
6. 通过临时只读前端预览源连接同一个 8001 模拟后端复核未提交工作区，预览源拒绝 POST/PUT/PATCH/DELETE；
7. 运行 Node/Python 回归测试并对关键首屏做人工目视复核。

没有读取或记录 `.env.*`、cookie、API Key、数据库 URL、交易所密钥或用户密码。没有点击会提交交易、治理或账号变更的确认动作。

## 3. 前端架构结论

| 关注项 | 当前实现 | 审计结论 |
|---|---|---|
| 框架 | FastAPI 提供原生 HTML/CSS/ES Modules | 架构轻量且与当前规模匹配；无需迁移 React/Vue |
| 路由 | `view-router.js` + History API | 11 个主视图、1 个兼容别名、独立登录页均已找到 |
| 状态 | `store.js::createState()` 内存态 | 页面、分页、筛选、刷新和错误所有权清楚 |
| 数据 | `/dashboard/bundle` 聚合 panel | 主批次/延迟批次减少首屏阻塞，panel key 有测试保护 |
| 实时性 | 30 秒轮询 + 人工刷新 | 当前没有 WebSocket；页面显示刷新时间和 freshness，不伪装成推送实时 |
| 组件 | HTML string renderer + 共享 `components.js` | 卡片、状态条、表格、dialog 和空态可复用；未发现需要大改的组件分裂 |
| 响应式 | 12 栏 CSS Grid + 记录卡 | 基础正确；本轮修正 1280px 断点和导航 |
| 无障碍 | 原生 landmark/dialog/label/reduced-motion | 本轮补 skip link、H1、main、aria-current；真实读屏器仍未测 |

## 5. 信息层级与空间利用

### 5.1 主页

首页首屏按“是否可交易 → 最近决策/委托/恢复限制/权益 → 登录会话与人工动作 → 次级摘要”排序。状态不是单个巨型数字；四项关键状态在一个紧凑 summary 区中。1280px 的会话与控制动作恢复同行显示，页面高度从约 2,173px 降至约 1,365px。

### 5.2 策略、风险和 AI 长页

这些页面长，不是因为空白卡片或固定高度，而是因为同时展示决策、候选、门禁、运行质量、历史归因和治理证据。本轮没有以隐藏关键风控为代价追求短页面；改用横向分区导航降低定位成本。自动测量未发现巨大空容器、固定 `vh` 或文档横向溢出。

### 5.3 表格与空态

桌面保留表格密度，窄屏使用记录卡。空态区分“无数据”“延迟加载”“授权失败”“查询失败”和“功能不可用”；没有把 backend error 变成空列表，也没有填充模拟数字美化页面。

## 6. 交易安全与风险表达

- “恢复自动运行”现在必须二次确认，确认文案说明后端仍会检查暂停开关、对账、恢复资格和全部风控门禁；审计 reason 仍为 `ui_manual_resume`。
- 暂停、重建基线、卡单恢复、RDP 审批/回滚等既有危险动作门禁未被削弱。
- 账号启停、角色修改和密码重置增加最终确认；确认消息不包含密码。
- 模拟环境、运行模式、可交易/暂停、人工复核、对账、exchange freshness 均有文字说明，不只依赖颜色。
- 没有修改策略、交易算法、风险限额、订单状态机或数据库 schema。

## 8. Loading、Error、Freshness 与性能

- 66/66 终检组合最终无 skeleton、无 `aria-busy`、无可见 error panel。
- 主 bundle 到达后页面可交互；延迟 bundle 不锁全页。refresh generation 与 AbortController 继续阻止旧响应覆盖新页面。
- 轮询周期和 view freshness 均为 30 秒；页面显示“最近刷新”，没有 WebSocket 也没有声称存在 WebSocket。
- 没有新增请求、endpoint、第三方库或渲染框架；布局整改不会增加后端负载。
- 基线浏览器 console warning/error 为 0。最终浏览器接口未提供 console/HAR 导出，故不声称完成最终 console/HAR 零错误证明；稳定渲染、可见错误和自动化测试作为当前证据。
