# Task189：风险页 Dashboard Bundle 首屏延迟优化 SOW

## 业务目标与边界
- 目标：降低风险页首次进入和手动刷新时的首屏等待时间，让页面先显示当前主任务、恢复资格、账户与对账核心信息，再补充低优先级诊断。
- 目标：解释并收敛 `/dashboard/bundle?view=risk` 的冗余请求组成，避免前端为同一批信息等待重复聚合。
- 边界：不修改任何风控、恢复、试盘守护、回放、退出任务的业务逻辑，不调整后端公开接口字段语义。
- 边界：只允许调整风险页 panel 取数编排、前端刷新流程和必要的 UI 加载提示。

## 模块职责与领域模型
- `aats/api/static/modules/store.js`
  - 负责定义各视图首包与延后补载的 panel 编排。
- `aats/api/static/app.js`
  - 负责风险页刷新流程、首包完成后的延后补载，以及刷新令牌防止旧请求覆盖新状态。
- `aats/api/static/modules/views/risk-view.js`
  - 负责在回放状态和退出任务长历史尚未补载时，给出明确的“正在补充”提示，而不是误导性的空状态。
- `/dashboard/bundle`
  - 继续作为统一聚合入口；本次不改鉴权和返回结构。

## 输入 / 输出接口
- 输入：`GET /dashboard/bundle?view=risk&panel=...`
- 输出：仍然返回现有 `{ view, panels, timing }` 结构。
- 前端内部新增：风险页首包与延后补载 plan；不新增新的公开 API。

## 数据库 Schema / 表 / 索引 / 约束
- 无数据库变更。
- 无迁移脚本。
- 无索引与约束调整。

## 事务、一致性与并发
- 不引入新的事务边界。
- 前端补载采用刷新令牌，旧的延后请求不得覆盖新的刷新结果。
- 后端仍保持单请求内既有查询一致性。

## 授权、认证与数据安全
- 不修改 `require_read_access` / `require_admin_access` 行为。
- 延后补载仍走同一鉴权链路和同一 bundle 接口。

## 错误处理与幂等
- 首包失败时保持现有错误处理。
- 延后补载失败时不影响核心首屏，只清理补载中的 UI 状态，避免永久显示“载入中”。
- 手动刷新与自动刷新保持幂等，不新增写操作。

## 状态流转与生命周期
- 风险页首包：先拉核心 panel，首屏尽快可用。
- 延后补载：首包成功后再拉 `replayStatus` 与 `exitExecutionActionHistoryPage`。
- 若用户在补载期间再次刷新，则旧补载结果丢弃。

## 缓存与性能
- 利用风险页现有 `runtime` / `metrics` 数据，删除与其重复的风险专属 panel 请求，减少同一 bundle 内重复聚合。
- 把低优先级且相对更慢的回放与退出任务长历史从首包拆出，降低首屏阻塞。

## 日志、监控与审计
- 不修改现有日志结构。
- 保留后端 bundle timing 返回，便于后续继续定位慢 panel。

## 测试策略
- 更新前端集成测试，验证风险页 bundle plan 会把低优先级 panel 延后补载。
- 更新前端源码断言，验证刷新流程使用新的 bundle request plan。
- 运行受影响的前端集成测试。

- 回滚方式：回退本次前端 panel 编排和刷新逻辑改动。
- 保持现有路由、字段和按钮动作兼容。

## 部署与验收标准
- 风险页首次进入不再等待完整回放与退出任务长历史后才显示主任务区。
- 风险页不再重复请求已经可从 `runtime` / `metrics` 直接复用的数据。
- 受影响前端集成测试通过。
