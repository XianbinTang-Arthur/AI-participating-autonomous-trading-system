# Recent Directional Decision Chain Density Truth SOW - 2026-04-30

## Business Objectives And Boundaries

Add a read-only runtime-truth surface that summarizes recent OKX `BTC-USDT-SWAP`
directional decision chain density across decision, order expectation, fill,
PnL lifecycle, microstructure, and command-flow provenance. The objective is to
make the trading microscope easier to monitor without changing strategy,
risk, execution, provider behavior, schema, symbols, venues, or timeframe
plumbing.

## Module Responsibilities And Domain Model

`scripts/runtime_truth_report.py` owns runtime evidence aggregation. The new
surface consumes existing sanitized truth surfaces and publishes compact status,
coverage counts, and interpretations. It does not query the database directly
and does not become a trading input.

## Input/Output Interfaces

Inputs:

- `directional_episode_attribution_truth`
- `decision_lifecycle_provenance_continuity_truth`
- `decision_lifecycle_execution_science_continuity_truth`
- `directional_command_flow_provenance_truth`

Output:

- `recent_directional_decision_chain_density_truth` in runtime truth reports
- projected fields in `runtime.live_runtime_facts`

## Database Schema / Tables / Indexes / Constraints

No schema, table, index, or constraint changes. The implementation reuses
existing runtime truth payloads generated by current probes.

## Transactions, Consistency, Concurrency

No writes and no transactions. Consistency is inherited from the single runtime
truth report snapshot.

## Authorization, Authentication, Data Security

No credentials are read or printed. The surface must not expose raw allocation
payloads, exchange payloads, API keys, tokens, or connection strings.

## Error Handling And Idempotency

Missing upstream surfaces produce explicit `status` and
`smallest_missing_field` values. The summarizer is pure and idempotent for a
given report.

## State Transition And Lifecycle

No runtime state transitions are introduced. The output only classifies the
current truth snapshot into verified, partial, or missing-evidence states.

## Caching And Performance

The surface performs O(1) aggregation over already summarized coverage fields
and at most a small recent-decision preview. It does not add database load.

## Logging, Monitoring, Auditing

The new report field improves monitoring and auditability by compacting recent
decision chain coverage into a single status with counts and missing fields.

## Testing Strategy

Add focused unit tests for:

- verified no-order expected regime
- missing order surface or no-order expectation
- live facts projection

Then run focused pytest, ruff for changed files, ruff for `aats/`, full unit
tests, and a post-change runtime truth report.

## Migration, Rollback, Compatibility

No migration required. Rollback is a normal git revert of the code and test
changes. Existing public report fields remain unchanged.

## Configuration And Environment Isolation

No configuration changes. The surface is environment-independent and relies on
the existing runtime truth generation path.

## Code Organization And Dependencies

Add one helper summarizer to `scripts/runtime_truth_report.py`, wire it into
report assembly, and expose selected fields in `project_live_runtime_facts`.
No new dependencies.

## Documentation And Operations Manual

This SOW documents the bounded change. Operators can read the runtime truth
report field directly or inspect projected `runtime.live_runtime_facts` fields.

## Deployment And Acceptance Criteria

Acceptance criteria:

- Runtime truth includes `recent_directional_decision_chain_density_truth`.
- No-order expected regimes verify only when recent decisions have no-order
  semantics and lifecycle/execution-science continuity is clean.
- Missing order surface or no-order expectation is reported as a concrete
  missing field.
- Raw payload exposure remains false.
- Focused tests, lint, full unit tests, deploy, and post-deploy runtime truth
  smoke pass.
