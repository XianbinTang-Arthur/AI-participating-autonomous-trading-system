# 现货运行模式链路复核与最小修复 SOW

## 业务目标与边界
- 目标：复核当前系统在 `spot` 运行模式下的全链路业务逻辑，定位一个明确且可复现的不合理点，并以最小改动修复。
- 边界：不改动现货主执行链的核心交易规则，不调整公共 API，不做无关重构。

## 当前行为摘要
- 现货运行域下，方向策略是 long-only，仓位可由快照仓位或现货余额兜底恢复。
- 现货风控会在买入时校验 quote 余额，在卖出时校验 base 余额。
- `smart_arbitrage` 在当前实现中只允许在 `derivatives` 运行域自动执行；现货运行域只会产出不兼容候选。
- 不合理点：当关闭自动选族、但手工把活动家族配置成现货运行域不兼容的家族时，多策略协调层仍会沿用该家族的“固定配置归因”，导致调度原因和运维摘要出现误导性信息。

## 模块职责与领域模型
- `StrategyCoordinatorService`：汇总各策略候选，决定选族并生成协调快照。
- `PortfolioAllocatorV2Phase2`：基于可执行 intent 计算最终账户级目标。
- `OperatorQueryService`：暴露 `/strategy/runtime` 等运行态摘要。

## 输入输出接口
- 输入：`DecisionContext`、`BaselineAssessment`、`PositionTarget`。
- 输出：`StrategyCoordinatorSnapshot`、最终应用后的 `PositionTarget`、运行态接口摘要。

## 数据库 / 事务 / 一致性 / 并发
- 本次修复不涉及数据库 schema、事务边界或并发模型变更。
- 修复点仅影响策略协调选择归因，不改变订单、成交、仓位落库逻辑。

## 鉴权 / 安全 / 审计
- 不涉及鉴权与凭证处理。
- 审计侧仅改善策略选择原因，降低运维误判风险。

## 错误处理与幂等
- 若固定配置家族在当前运行域不可执行，应显式回退到 `directional` 并记录回退原因。
- 保持现有候选评估与目标生成幂等性。

## 状态流转与生命周期
- 仅调整“固定家族选择”分支：
- 当固定家族可执行时，保持原行为。
- 当固定家族在当前运行域不可执行时，直接回退到 `directional` 作为选择结果，并记录回退原因。

## 缓存 / 性能
- 本次修复为常量级分支判断，不引入新的 I/O 或缓存。

## 日志 / 监控 / 运行手册
- 通过 `selection_reason_codes` 与运行态摘要暴露更准确的回退原因。
- 不新增日志字段。

## 测试策略
- 单元测试：覆盖现货运行域下固定 `smart_arbitrage` 且关闭自动选族时的回退行为。
- 集成测试：覆盖 `/strategy/runtime` 暴露的 `latest_selected_family` 与 `latest_selection_reason_codes`。

## 迁移 / 回滚 / 兼容性
- 无数据迁移。
- 回滚只需回退本次代码提交。
- 保持现有 API 结构不变，仅修正字段语义。

## 配置与环境隔离
- 不新增配置项。
- 不修改现有现货/合约 profile 文件。

## 代码组织与依赖
- 仅修改策略协调器与测试文件。
- 不新增第三方依赖。

## 文档与验收标准
- 验收标准：
- 现货运行域固定到不兼容家族时，最终选中家族回退为 `directional`。
- 调度原因包含明确 fallback 标识，不再出现误导性的“已按固定家族选中”归因。
- 单元测试、最小集成测试与校验命令通过。
