# AATS 文档治理规范

> 文档状态：现行约束  
> 最后核对：2026-08-23（代码基线 `be9179ead5be6aba22fbe94e3baf72b9f46eedc3`）  
> 核对范围：仓库内 Markdown 文档、文档目录、入口链接、生命周期与静态真源  
> 不覆盖：当前容器、数据库、交易所账户、订单、仓位、告警或资金安全状态

本规范定义 AATS 文档的放置、命名、状态、复核和迁移规则。它用于阻止历史任务书、设计稿或一次性运行记录被误当成当前实盘操作依据。

## 1. 文档真源与冲突裁决

文档描述固定行为时，按下列顺序裁决：

1. 当前代码、数据库迁移、配置生成器、Compose 声明、部署与运维脚本；
2. 当前测试对行为契约的验证；
3. 已在当前基线核对的根入口和现行操作文档；
4. 专题参考；
5. 带日期的设计、任务、审查、审计、观察和会话记录。

任何静态材料都不能证明实时余额、仓位、订单、active parameter version、kill switch、reconciliation、容器健康、交易所模式或 trading-ready 状态。此类事实必须在操作当时通过受控 UI/API、只读数据库或标准健康检查重新取得。

## 3. 放置规则

- 新的长期入口或跨模块规范放在 `docs/` 根层，但必须先确认不存在等价最高层入口。
- 新的本地测试说明放在 `docs/testing/`；部署步骤只写入根 `DEPLOYMENT.md`，其他文档链接它。
- 新的运行操作写入 `docs/operations/`，并在 `docs/operations/README.md` 登记状态、范围和真源。
- 新的配置说明写入 `docs/configuration/`，代码生成内容不得手工维护两份。
- 新的 SOW、实施计划和交付记录写入 `docs/task/`，不得再写入 `docs/` 根层。
- 新的审查、审计、设计、研究和会话材料进入同名目录，不得因“重要”提升为当前入口。
- 生成报告优先写入被 `.gitignore` 管理的 artifact 目录；只有需要长期审计的摘要才进入 `docs/`。

截至 2026-08-23，`docs/` 根层仍保留 184 份历史 SOW/任务材料。这是为了保持提交、Issue、审计和外部链接稳定的兼容区，不是推荐结构；禁止继续向该兼容区增加同类文件。

## 4. 命名规则

- 目录统一使用小写 `snake_case`；禁止新增带空格目录。
- 稳定入口使用职责名，例如 `README.md`、`module_reference.md`，不带日期。
- 一次性快照在文件名末尾使用 `YYYY_MM_DD`；现有历史命名不为美观而批量改写。
- 文件名使用英文小写 `snake_case`；标题和正文使用准确、正式的 UTF-8 中文。
- `README.md` 是目录入口。存在两份以上、或存在不同生命周期文档的目录必须有入口页。
- 不以 `final`、`latest`、`new`、`temp` 表示长期状态；状态应写入元数据和目录索引。

## 5. 生命周期元数据

现行或专题参考文档应在标题后提供：

```text
> 文档状态：现行操作说明 / 现行参考 / 专题参考 / 历史快照 / 已废弃
> 最后核对：YYYY-MM-DD（代码基线 `<full-or-short-commit>`）
> 核对范围：静态代码 / 测试 / 受控运行时（按实际填写）
> 当前替代：仅历史或已废弃文档填写
```

规则如下：

- “最后核对”只证明列出的范围；不能把静态检查写成运行时验证。
- 现行操作说明超过 30 天，或其脚本/API/安全门变化后，自动进入待复核。
- 现行架构和模块说明超过 90 天，或模块/模型/控制流变化后，自动进入待复核。
- 历史快照保持当时事实，只补充醒目的历史边界、断链修复和当前替代入口。
- 已废弃文档必须说明停止使用原因和替代入口；删除前先全仓搜索代码、测试和外部约定。

## 6. 迁移与兼容

文档迁移前必须完成：

1. 全仓搜索旧路径、文件名和标题引用；
2. 判断代码、测试、CI、脚本和外部审计是否依赖该路径；
3. 使用一次变更完成移动和仓库内链接修复；
4. 执行本地 Markdown 链接检查；
5. 在目录入口记录新位置或保留策略。

高引用、带审计意义的历史路径默认原地保留。结构整洁不能凌驾于可追溯性；需要迁移时，应有独立迁移清单而不是无差别批量重命名。

## 7. 内容质量要求

- 先写目的、适用范围、前置条件、停止边界，再写步骤。
- 命令必须声明执行环境；Windows PowerShell 与 WSL2 命令不得混写。
- 涉及状态变更时，必须写审批、安全门、验证和恢复路径。
- 禁止记录或示例化真实密钥、密码、token、账户标识和 `.env.*` 内容。
- 数量、端口、profile、Topic、表、route 和 workflow 等易漂移事实必须链接代码真源。
- “已修复”“已上线”“运行正常”“资金安全”等结论必须附验证范围和时间；没有现场证据时写“未知/待验证”。
- 大段代码复制应替换为稳定的文件/符号链接和行为说明，避免两套实现文档。

## 8. 变更验收

文档变更至少验证：

- 仓库内 Markdown 链接和图片目标存在；
- 新增目录有 `README.md`；
- 现行文档包含日期、基线、范围和运行时未知边界；
- 当前入口没有链接到已废弃命令；
- 未读取、复制或输出任何凭证；
- 若同时改动代码，按 `AGENTS.md` 执行 lint、单元测试和最窄集成测试。

本轮结构与内容审计见 [`code_review/DOCUMENTATION_AUDIT.md`](code_review/DOCUMENTATION_AUDIT.md)。
