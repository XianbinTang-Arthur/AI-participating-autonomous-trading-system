# Task36 UI 审查问题收口 SOW

## 业务目标和边界

本次收口只处理 operator 控制台的用户可见展示问题：隐藏调试原文、统一中文术语、修正当前状态与历史结果混写、补齐按钮不可用原因、改善窄屏布局。不会修改交易决策、风控规则、下单执行、数据库数据或运行配置。

## 模块职责和领域模型

- `terms.js` 负责把后端枚举、reason code、运行模式和诊断短语转成中文。
- `formatters.js` / `components.js` 负责通用展示组件、空态、按钮和调试原文折叠。
- `detail-drawers.js` / `shadow-drawer.js` / `lifecycle-drawer.js` 负责详情抽屉信息层级。
- `shell-renderer.js` 负责全局运行模式、首页状态带和刷新交互。
- `ai-*`、`risk-view.js`、`rdp-*` 负责页面级业务摘要。

## 输入输出接口

输入仍为现有 dashboard bundle、详情接口和 blocker/control payload。输出仅为前端 HTML/CSS/JS 渲染结果，不新增公开 API。

## 数据库和一致性

不变更表、索引、约束或持久化数据。不存在数据库迁移。OrderState 三层持久化不受影响。

## 事务、并发和幂等

本次不引入新的写操作。原有人工动作仍走既有 `runAction` / `runDangerousAction` 流程。刷新锁只影响按钮展示和可点击状态，不改变后端幂等语义。

## 鉴权和数据安全

不读取或展示凭证。调试 JSON 默认折叠，普通操作员首屏不直接看到 raw payload。按钮仍按现有 `operator` / `admin` 权限控制。

## 错误处理和空态

新增/强化共享本地化和诊断文案处理：未知内部 code 不再原样暴露为下划线字符串；缺失数据明确显示为未采集、未启用或暂无样本。

## 状态转换和生命周期

不改变系统状态机。页面文案明确区分当前仍生效状态、最近一次结果、历史记录和调试上下文。

## 缓存和性能

不新增接口请求。折叠调试原文减少首屏视觉噪声；不改变自动刷新周期。

## 日志、监控和审计

不新增后端日志。前端仍保留 console 诊断。用户可见层减少 raw code 泄漏。

## 测试策略

补充/更新前端静态和渲染回归测试，重点覆盖运行模式 badge、抽屉 raw JSON 默认折叠、未知 reason code 中文化、AI 降级原因、影子详情按钮和 RDP 证据文案。

## 迁移、回滚和兼容性

静态前端改动可直接通过 git 回滚。保留现有函数名和模块边界，避免破坏 import。

## 配置和环境隔离

不改 `.env*`、运行 profile 或部署配置。验证使用 Windows `.venv\Scripts\python.exe`，浏览器复查使用当前 HTTPS 本地控制台。

## 代码组织和依赖

优先复用现有 `terms.js`、`copy.js`、`components.js`，不新增外部依赖。

## 文档和运维手册

本文档作为本轮 UI 收口的实施说明。现有 `docs/task/task36.md` 继续作为总体诊断标准。

## 部署和验收标准

验收标准：主要页面和抽屉不再首屏显示 raw code / raw JSON；状态语义更清晰；影子详情可打开或明确说明不可用原因；窄屏运行模式 badge 不再溢出；相关测试通过。
