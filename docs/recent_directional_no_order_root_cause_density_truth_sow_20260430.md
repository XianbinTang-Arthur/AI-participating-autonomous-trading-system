# Recent Directional No-Order Root Cause Density Truth SOW

## Business Objectives And Boundaries

Expose a read-only runtime truth surface that explains why recent OKX BTC-USDT-SWAP directional decisions did not create orders. The scope is diagnostic evidence density only. It must not change strategy logic, risk gates, execution behavior, provider behavior, schemas, symbols, venues, strategy families, release logic, promotion logic, tuning, or timeframe plumbing.

## Module Responsibilities And Domain Model

`scripts/runtime_truth_report.py` owns the runtime truth summary. The new surface summarizes recent directional no-order semantics from the existing directional episode attribution truth. Domain entities are recent directional decisions, order expectation, no-order semantics, root cause, root materiality, route action, and equivalence class.

## Input/Output Interfaces

Input is the already-sanitized `directional_episode_attribution_truth` payload generated by the runtime truth report. Output is a new JSON object, `recent_directional_no_order_root_cause_density_truth`, plus projected live facts. No raw exchange payloads or credentials are emitted.

## Database Schema / Tables / Indexes / Constraints

No schema, table, index, or constraint changes. The implementation uses existing runtime truth aggregation only.

## Transactions, Consistency, Concurrency

No writes to the trading database. The surface is generated within the existing read-only runtime truth report flow and inherits its consistency model.

## Authorization, Authentication, Data Security

No credentials are read or printed. The surface does not add authenticated API calls and does not change AI/runtime auth behavior. Existing auth-gated AI runtime semantics remain unchanged.

## Error Handling And Idempotency

Missing attribution, missing recent decisions, missing order expectation, missing no-order semantics, missing root cause, and missing root materiality produce explicit status and smallest missing field values. The report is idempotent for the same input.

## State Transition And Lifecycle

No live order, position, lifecycle, or state transition is modified. The surface classifies diagnostic evidence only.

## Caching And Performance

The implementation adds compact in-memory distributions over the existing recent decision sample. It avoids new database queries and keeps output bounded.

## Logging, Monitoring, Auditing

The generated runtime truth JSON and projected live facts become the audit artifact. No application logs are changed.

## Testing Strategy

Add focused unit tests for verified no-order root cause density, missing no-order semantics, and live facts projection. Run focused tests, ruff, and the required unit validation suite.

## Migration, Rollback, Compatibility

No migration is required. Rollback is a normal code revert of the runtime truth surface and tests. Existing fields remain backward compatible.

## Configuration And Environment Isolation

No new configuration or environment variables. The surface works in the existing Windows runtime truth command and deployed WSL2 profile.

## Code Organization And Dependencies

Keep all logic in `scripts/runtime_truth_report.py` with tests in `tests/unit/scripts/test_runtime_truth_report.py`. No new third-party dependencies.

## Documentation And Operations Manual

This SOW documents the task boundary and acceptance criteria. Operators can inspect the new truth surface in generated runtime truth artifacts.

## Deployment And Acceptance Criteria

Acceptance is binary:

1. Runtime truth includes `recent_directional_no_order_root_cause_density_truth`.
2. The surface reports verified status when recent directional decisions are all no-order expected with complete stable root semantics.
3. The surface reports an explicit missing field when no-order root semantics are incomplete.
4. Live facts project status, counts, top root cause, and materiality interpretation.
5. Focused tests, required lint/unit validation, deploy, and post-deploy smoke pass without changing live trading behavior.
