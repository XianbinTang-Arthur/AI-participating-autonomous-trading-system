# Task 85: 刷新态按钮锁定

## 业务目标与边界
- 目标：当当前页面、打开中的抽屉或其内部展示卡片处于刷新态时，所有按钮必须变灰并不可点击，避免“看起来能点，但请求不会发出”的误导体验。
- 边界：只处理前端控制台刷新期间的按钮可用性，不改后端接口语义，不扩展到导航链接或非按钮输入控件。

## 模块职责与领域模型
- `aats/api/static/app.js`：统一管理页面刷新状态，收集当前需要进入刷新锁定的交互区域。
- `aats/api/static/modules/refresh-interactivity.js`：按刷新状态批量锁定/恢复按钮，并保证只恢复本轮刷新期间临时锁定的按钮。
- 领域状态：
  - `refreshing=true`：当前活动页面正在拉取最新面板数据。
  - `refresh_locked`：按钮因刷新态被临时禁用，不改变其原始业务禁用原因。

## 输入 / 输出接口
- 输入：
  - 当前活动视图根节点
  - 打开中的详情抽屉根节点
  - `refreshing` 布尔状态
- 输出：
  - 对应区域内按钮的 `disabled` 状态
  - 刷新态提示 `title`

## 数据库 / 事务 / 一致性 / 并发
- 无数据库变更。
- 无事务变更。
- 一致性要求：刷新开始和结束都必须重新同步按钮状态，不能把原本业务上禁用的按钮误恢复。
- 并发要求：页面刷新和人工动作串行于前端状态机；刷新锁定只覆盖当前刷新窗口。

## 鉴权 / 安全
- 不改变现有权限控制。
- 刷新锁定优先级低于原有鉴权禁用，只补充前端交互保护。

## 错误处理与幂等
- 同一轮刷新重复调用锁定函数应保持幂等。
- 刷新结束重复恢复应保持幂等。

## 状态流转与生命周期
- 进入刷新：
  - 收集当前活动页面和已打开抽屉。
  - 将其中所有按钮置灰禁用。
- 刷新结束：
  - 只恢复本轮刷新临时锁定的按钮。
  - 原本就禁用的按钮保持禁用。

## 缓存 / 性能
- 只遍历当前活动页面和已打开抽屉，不扫描整个文档，避免不必要 DOM 操作。

## 日志 / 监控 / 审计
- 无新增日志、监控和审计事件。

## 测试策略
- 单测：验证刷新锁定会禁用页面和抽屉按钮，并在刷新结束后只恢复临时锁定按钮。
- 集成测试：验证静态资源已接入刷新态按钮锁定模块，并暴露用户提示文案。

## 迁移 / 回滚 / 兼容性
- 无数据迁移。
- 回滚方式：移除刷新态按钮锁定模块接入即可。
- 兼容性：不改 public API，不影响现有按钮权限判断。

## 配置与环境隔离
- 无新增配置项。

## 代码组织与依赖
- 新增前端模块 `refresh-interactivity.js`，由 `app.js` 引入。
- 不引入第三方依赖。

## 文档与运维
- 运维无需额外操作。
- 页面刷新期间的按钮禁用完全由前端自动处理。

## 部署与验收标准
- 当前活动页面刷新时，页面内按钮全部变灰不可点击。
- 抽屉打开时若页面刷新，抽屉内按钮和关闭按钮一并变灰不可点击。
- 刷新结束后，临时禁用按钮恢复；原本因权限或业务条件禁用的按钮保持原状。
