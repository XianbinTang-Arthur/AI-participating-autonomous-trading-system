# AATS 全前端布局与信息密度优化 SOW

> 文档状态：已完成实施；尚未部署到标准 derivatives 栈
> 日期：2026-08-25
> 起始提交：`150f6b8d5fe3231251e48f8e7b19e8c024e03359`
> 分支：`main`
> 验证环境：`127.0.0.1:8001` derivatives 本地模拟栈；只读页面核查，不触发交易或管理动作
> 真实性边界：基线高度和空白数据来自上述提交对应前端在 1280 × 720 浏览器视口下的当前运行页面；页面数据变化会影响绝对高度，因此验收以布局结构、溢出和相对空白改善为主。

## 1. 业务目标与边界

本任务优化 AATS Operator 控制台登录后全部 11 个前端路由的页面布局、公共间距、卡片密度、表格密度和响应式编排，重点消除同一网格行因内容高度差异产生的大面积无效空白，使值班人员在不牺牲交易安全信息、字段完整性和可读性的前提下，更快完成扫描、比较和下钻。

范围包括共享 shell、全局 CSS 布局原语、主页、交易总览、策略、执行、风险、退出任务、回放、AI 分析、AI 配置、RDP 和账户权限页面。范围不包括业务状态语义、交易算法、下单路径、风控参数、后端接口、数据库、认证授权和 live profile 放行。不得通过隐藏字段、截断关键证据或缩小点击目标来换取视觉紧凑。

## 2. 模块职责与领域模型

- `aats/api/static/app.css`：密度 token、页面容器、12 栏网格、卡片、列表、表格、响应式断点和新增独立列流布局原语。
- `modules/views/strategy-view.js`：策略结论、执行约束、决策记录、自动试盘和归因布局。
- `modules/views/risk-view.js`：恢复资格、对账、保证金、账户、敞口、阻断和复盘布局。
- `modules/views/ai-analysis-view.js`：AI 状态、决策链、档位证据、表现和历史布局。
- `modules/views/rdp-control-panel.js`：当前待处理、调优、后台状态、阻断和观察窗口的两栏负载分配。
- 其余页面继续使用共享 `panel-grid`、`workspace-stack`、`surface-card`、`summary-strip` 和表格原语，自动获得全站密度优化。

领域数据、状态派生和动作入口保持原样；本任务只改变展示编排。

## 3. 输入与输出接口

输入是真实代码、现行文档、11 个页面路由的运行 DOM、1280 × 720 基线尺寸和当前模拟运行数据。输出包括本 SOW、共享 CSS 变更、四个重点页面的结构性重排、布局契约测试和复验记录。

不得修改公共 URL、DOM 中动作的 `data-action` / `data-value`、后端 endpoint、JSON 字段或既有权限条件。已有自动化测试依赖的状态文案保持兼容。

## 4. 数据库、表、索引与约束

不修改数据库 schema、表、索引、约束、迁移或种子数据。布局验收不得依赖修改运行数据来制造更短页面。

## 5. 事务、一致性与并发

不修改刷新 generation、请求取消、分页、mutation in-flight、目标 panel 失效或 stale-while-revalidate 逻辑。DOM 重排不得复制卡片或动作节点，避免同一动作出现两个入口或重复事件绑定。

## 6. 授权、认证与数据安全

保持 viewer/operator/admin 的现有可见性和可操作性。验证只读取页面结构、尺寸、标题、控制台和非敏感请求状态；不读取 Cookie、localStorage、`.env.*`、API key、密码或交易所凭证，不点击交易、恢复、账号或 RDP 写操作。

## 7. 错误处理与幂等

loading、empty、error、stale、unsupported 和 authorization blocked 的卡片仍使用同一布局原语，不能因缺少某个可选卡片造成非法列宽、孤立空行或 DOM 结构损坏。条件渲染的 replay/复盘区必须在有无可选卡片时都保持有效。

## 8. 状态迁移与生命周期

页面 route resolve、初始骨架、primary bundle、deferred panel 和自动刷新生命周期保持不变。重排只在每次纯函数 render 的 HTML 中发生，不新增持久 UI 状态，也不改变 HALTED、degraded、unknown、resume eligible 等状态的视觉优先级。

## 9. 缓存与性能

不新增第三方依赖、网络请求、图片或运行时布局脚本。采用 CSS Grid 和现有服务端静态资源；新增布局原语应避免固定高度和 JavaScript 测高。压缩后的页面应减少滚动距离，不应产生 layout thrashing 或页面级横向滚动。

## 10. 日志、监控与审计

浏览器复验记录每个路由的文档高度、重点网格卡片高度、页面横向溢出、console error 和失败请求。绝对高度只作为当次模拟数据快照，不作为未来运行状态的永久真相。代码不新增日志或审计事件。

## 11. 测试策略

- 静态契约：密度 token、独立列流布局、1100px 降级、重点页面分组和 RDP 卡片归属；
- 前端集成：现有 dashboard UI 测试，确保视图渲染、条件卡片、动作和文案不回归；
- 通用验证：Ruff 和完整 unit suite；
- 浏览器：11 个路由全部复验，重点检查策略、风险、AI 分析、RDP，并抽查窄屏断点；
- 安全：验证过程中不执行任何 mutation。

## 12. 迁移、回滚与兼容

无数据迁移和构建迁移。回滚可按本任务 CSS、四个视图文件、测试和文档的 Git diff 完成。原有类名和布局原语保持可用，新增类为 additive；公共动作和 API 完全兼容。

## 13. 配置与环境隔离

只使用已运行的 derivatives 本地模拟栈观察现状。代码验证不启动 live profile，不修改环境配置，不读取凭证。若需要加载未部署静态资源，应使用只读预览并拒绝写方法；未提交代码不得通过非标准同步方式部署到 WSL2。

## 14. 代码组织与依赖

优先在 `app.css` 建立统一密度 token 和独立列流 primitive，页面文件只表达业务分组，不重复硬编码间距。继续使用原生 HTML/CSS/ES modules；不引入框架、CSS 库、masonry 运行时或新包。

## 15. 文档与操作手册

本 SOW 位于 `docs/task/`，符合现行文档治理。由于本任务不改变操作流程、路由或安全语义，无需重写操作手册；若实施过程中发现入口或语义必须改变，应停止并另行更新现行操作文档。

## 16. 部署与验收标准

当前 1280 × 720 基线中，策略页首组卡片高度约 625 / 2311 / 1011px，风险恢复区两行存在最高约 159px 的行内差，AI 分析首行存在约 1046px 的空列，RDP 两栏相差约 680px。验收要求：

- 11 个页面均应用统一密度 token，卡片、列表、表格和分区间距明显收敛但正文与点击目标仍可读可用；
- 策略结论组改为独立列流，决策记录填补短列，不能再由最长卡片强制产生同量级空洞；
- 风险恢复组使用三条独立内容列，常规阻断/指标/账单组使用独立列堆叠；
- AI 分析的状态与档位证据、决策链与表现分别成列，消除首行等高网格的千像素级空白；
- RDP 后台状态移入较短主列，使两栏负载更均衡；
- 1100px 及以下新增列流退化为单列，720px 及以下原有移动表格卡片和横向分区导航继续有效；
- 所有主路由无页面级横向溢出、遮挡、重复动作或新增 console error；
- 自动化测试、Ruff 和 unit suite 通过；未完成的真实多视口或部署后验证必须明确标为未验证，不得推断成功。

实施后只读预览在同一 1280 × 720 视口下复测，11 个路由的文档高度依次由约 `1365 / 3065 / 9109 / 1633 / 4234 / 977 / 961 / 6415 / 2077 / 3101 / 1477px` 收敛为 `1267 / 2791 / 7357 / 1430 / 3682 / 900 / 860 / 5008 / 1921 / 2513 / 1378px`。重点结构中，策略首组两列高度收敛为约 `1682 / 2073px`，风险常规复盘两列约 `377 / 340px`，RDP 两列约 `1939 / 1932px`；全部路由的 `scrollWidth` 与 `clientWidth` 一致。该结果证明当前模拟数据快照和 1280px 视口下的改善，不替代部署后、多视口、真实 live 数据或屏幕阅读器验收。
