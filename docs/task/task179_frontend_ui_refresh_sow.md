# Task179：前端工作台界面梳理与信息映射收口 SOW

> 项目定位声明：本文件默认服从 AATS 的统一目标：在严格风控、可审计、可恢复、可治理前提下，通过自动化交易追求长期稳定盈利，为 AI 的持续自治与终身发展积累资本。详见 [项目定位声明](../../docs/project_positioning.md)。


## 业务目标与边界

- 目标：提升当前 Operator UI 的可读性、信息层级、表格可用性和中文表达质量，让值班用户更快看懂“现在发生了什么、是否要处理、下一步该做什么”。
- 目标：修复默认折叠、高密度杂讯、后端语义直出、横向拖拽表格、空白与布局失衡等最影响观感和使用效率的问题。
- 边界：不修改任何交易、风控、对账、恢复、AI、回放的业务逻辑，不新增或变更后端接口。
- 边界：只调整 `aats/api/static/` 下的静态页面、样式、渲染结构、前端文案映射，以及与之对应的前端集成测试。

## 模块职责与领域模型

- `dashboard-shell.html` / `app.js`
  - 负责工作台外壳、导航、页面级刷新与视图切换。
- `app.css`
  - 负责全局视觉层、栅格、卡片、表格、抽屉、响应式行为。
- `modules/components.js`
  - 负责通用卡片、摘要条、表格、移动端记录卡、按钮等基础组件。
- `modules/terms.js`
  - 负责把后端状态码、原因码、内部字段转成用户可读的中文文案。
- `modules/views/*.js`
  - 负责各页面的信息架构与“什么该前置展示、什么该降级展示”。

## 输入输出接口

- 输入：现有 `/dashboard/bundle` 与各面板接口返回的数据结构。
- 输出：不改接口字段，只改变前端如何组织、映射、折叠、排序和展示这些字段。
- 兼容性要求：已有按钮 `data-action`、抽屉入口、分页动作、页面路由保持不变。

## 数据库 Schema / 表 / 索引 / 约束

- 无数据库变更。
- 无迁移脚本。
- 无索引或约束调整。

## 事务、一致性与并发

- 本次改动为前端展示层改动，不引入新的事务边界。
- 仍沿用现有刷新逻辑、面板 bundle 拉取逻辑和按钮交互节流逻辑。

## 授权、认证与数据安全

- 不改登录、会话、权限判断与 API 调用行为。
- 仅确保前端在展示时继续遵守既有权限门控，不新增绕过入口。

## 错误处理与幂等

- 保持现有空状态、错误状态、刷新状态与按钮 pending 状态。
- 前端文案映射增强时，未知字段仍回退到现有兜底逻辑，不制造新的渲染异常。

## 状态迁移与生命周期

- 页面级生命周期保持现状：加载、刷新、展示、详情抽屉、分页。
- 会调整部分内容的默认展开/默认前置展示策略，但不改变对应业务状态本身。

## 缓存与性能

- 优先复用现有渲染路径，不引入新框架。
- 通过减少首屏无效信息和降低横向溢出，提高可扫描性，同时避免增加请求次数。

## 日志、监控与审计

- 不改后端日志。
- 不改审计事件。
- 前端本轮无需新增埋点。

## 部署与验收标准

- 首页、交易总览、策略判断、委托与成交、风险与恢复、回放与复盘的视觉层级更清晰。
- 高频核心信息默认可见，不再把关键判断默认折叠。
- 主要页面不再依赖桌面横向拖拽才能看全核心表格。
- 后端内部语义在前端有更稳定的中文映射，减少直接暴露英文/内部术语。
- 前端集成测试更新并通过。
