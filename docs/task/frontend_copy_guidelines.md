# 前端文案规范

## 目的

这份规范用于统一前端页面中的中文文案风格，减少同义词混用、状态语义冲突、空状态表达不一致、标题口径漂移等问题。

后续新增页面、调整文案、补充状态卡片、扩展抽屉、增加表格列名时，都应优先遵循这份规范。

## 总体原则

1. 全站使用干净、自然、可读的 UTF-8 中文。
2. 同一类对象必须使用同一类命名，不要同页混用近义词。
3. 标题负责定性，说明负责解释当前状态和下一步动作。
4. 文案应尽量贴近事实，不夸大、不提前下结论。
5. 空状态统一，避免同一系统里出现“最近没有”“当前还没有”“暂无”“没有新的”混写。
6. 能用短名词短语的地方，不用口语化整句。

## 术语表

下列术语为优先使用词。

### 运行与恢复

- `自动运行`
- `可交易`
- `待恢复`
- `已暂停`
- `已阻断`
- `恢复受限`
- `待人工确认`
- `持续观察`
- `允许执行`

### 决策与 AI

- `决策链路`
- `真实决策链路`
- `策略档位`
- `实盘授权`
- `对账未达一致`

### 对账与风险

- `对账概览`
- `对账记录`
- `阻断记录`
- `回放记录`
- `账单概览`
- `对账处置`

## 禁止混用词

除非是历史数据原文，否则不要再新增以下写法：

- `主链`
- `档位控制` 作为泛称时
- `放权`
- `不干净`
- `暂不允许恢复`
- `已放行`
- `被拦截`
- `仅提示`
- `观察中`
- `详情 / 查看 / 查看详情` 混杂使用

推荐替换为：

- `主链` -> `决策链路`
- `放权` -> `实盘授权`
- `不干净` -> `对账未达一致`
- `已放行` -> `允许执行`
- `被拦截` -> `已阻断`
- `观察中` -> `持续观察`

## 标题规范

### 状态标题

状态型标题统一使用：

- `当前状态：X`

示例：

- `当前状态：待恢复`
- `当前状态：已阻断`
- `当前状态：需先完成对账`
- `当前状态：恢复受限`
- `当前状态：持续观察`

适用场景：

- 首页主状态
- 风险页主状态
- 总览页无新动作时的主标题
- 关注事项卡片
- 需要明确表达当前系统状态的提醒卡片

### 卡片标题

卡片标题优先落在以下名词集合中：

- `概览`
- `记录`
- `明细`
- `处置`
- `结论`
- `说明`
- `状态`
- `指标`

推荐模式：

- `账户概览`
- `执行概览`
- `对账概览`
- `账单概览`
- `执行异常`
- `决策记录`
- `对账记录`
- `阻断记录`
- `回放记录`
- `策略结论`
- `信号说明`

避免：

- `当前最需要处理的问题`
- `最近一次关键动作`
- `第一屏判断依据`
- `决策历史、影子对比与长期表现`

这类标题不是不能用，但优先拆成更短、更稳定的名词标题。

## 说明文案规范

### 状态说明模板

状态说明统一使用：

- `当前处于 X 状态。`
- `当前需先完成 X。`
- `当前暂无 X。`

然后再补下一步动作：

- `请先...`
- `确认无误后可...`
- `建议先...`

示例：

- `当前处于手动暂停状态。确认最新对账和账户快照无误后，可直接恢复自动运行。`
- `当前处于恢复受限状态。请先满足恢复条件后再恢复自动运行。`
- `当前需先完成对账。确认没有高风险差异后，再决定是否恢复自动运行。`
- `当前仍需人工确认。请先核对交易所状态与本地记录，再决定是否接受为新基线。`

### 说明文案要求

1. 先说当前状态，再说下一步。
2. 不要把状态、原因、动作混成一长句。
3. 不要把建议写成已经完成的事实。
4. 不要把启发式判断写成确定结论。

## 按钮文案规范

按钮统一使用“动词 + 对象”格式。

推荐动词：

- `查看`
- `重新`
- `确认`
- `恢复`
- `暂停`
- `加载`
- `收起`

推荐示例：

- `查看最新对账`
- `查看决策链`
- `查看详情`
- `重新对账`
- `确认为新基线`
- `恢复自动运行`
- `暂停自动运行`
- `加载更多对账记录`

避免：

- `详情`
- `查看`
- `查看并处理`

如果按钮确实承担两层语义，才可使用复合动作，例如：

- `查看并处理`

## 抽屉标题规范

抽屉统一使用：

- `X 详情`
- `当前记录：ID`

推荐结构：

- `eyebrow`: `决策链详情 / 委托详情 / 成交详情 / 对账详情`
- `title`: `当前记录：xxx`

避免标题直接重复业务编号，缺少类型信息。

## 表格列名规范

表格列名优先使用统一集合：

- `记录时间`
- `状态`
- `摘要`
- `结果摘要`
- `操作`
- `记录编号`

分场景补充：

- `对账级别`
- `停机要求`
- `门禁状态`
- `影响摘要`
- `差异摘要`

推荐示例：

- `记录时间 / 对账级别 / 差异摘要 / 停机要求 / 操作`
- `记录时间 / 标的 / 结论摘要 / 门禁状态 / 操作`
- `记录时间 / 状态 / 净收益差 / 复核状态 / 回放上下文`

避免：

- `时间`
- `查看`
- `详情`
- `级别`

这类过短列名在不同页面容易歧义。

## kicker 副标题规范

kicker 统一使用 2 到 4 个字的名词短语，不写整句。

推荐：

- `问题处置`
- `操作前提`
- `资金状态`
- `动作摘要`
- `提醒信息`
- `执行状态`
- `风险提示`
- `关键链路`
- `核心指标`
- `历史记录`
- `运行状态`
- `最新结果`
- `执行边界`

避免：

- `先回答 AI 现在到底有没有真实参与`
- `做动作前先看`
- `为什么会得出这个结论`
- `系统刚刚做了什么`

这类句子应放到 `copy`，不应作为 kicker。

## 空状态规范

空状态统一使用：

- `当前暂无...`

推荐示例：

- `当前暂无委托记录。`
- `当前暂无成交记录。`
- `当前暂无对账记录。`
- `当前暂无阻断项。`
- `当前暂无新的次级提醒。`
- `当前暂无可展示数据。`

避免：

- `当前还没有...`
- `最近还没有...`
- `最近没有新的...`
- `当前没有新的...`

说明：

- 如果强调“当前没有”，默认一律改成 `当前暂无`
- 除非文案必须表达时间趋势，否则不要写 `最近`

## 指标文案规范

指标卡里的三层结构保持固定：

1. `label`: 说明看什么
2. `value`: 当前结果
3. `meta`: 补充上下文

要求：

1. `label` 尽量短
2. `value` 优先用状态词表
3. `meta` 只补充事实，不写判断口号

示例：

- `恢复状态 / 待恢复 / 当前处于手动暂停，可在确认后恢复自动运行`
- `对账级别 / 账实一致 / 已比对交易所`

## 历史记录与当前状态的区分

凡是历史记录页、历史抽屉、历史表格，必须明确区分：

- 这是历史记录
- 操作会作用于当前运行态

推荐文案：

- `这是历史对账记录。下面的操作会作用于当前运行态，请先确认最新对账结论是否仍然一致。`

## 风险与建议文案规范

建议文案只写“建议”，不要写成“系统已替你判断完成”。

推荐：

- `建议去交易所核对并撤销异常挂单`
- `建议去交易所核对并处理异常仓位`
- `确认属实后纳入新基线`
- `先观察，不建议立即处理`

避免：

- `去交易所撤单`
- `去交易所平仓`

如果系统还没有自动执行能力，就不要写成命令式结论。

## 事实一致性要求

文案必须和后端真实语义一致。

重点注意：

1. 累计指标不能写成当前待处理数量。
2. `CLEAN` 不能渲染成告警语义。
3. 手动暂停不等于永久不可恢复。
4. 启发式建议不能写成确定性裁决。
5. 历史记录不能假装是当前状态。

## 编码要求

1. 所有新增前端文件必须以 UTF-8 保存。
2. 禁止出现乱码字符。
3. 禁止引入半中半英的脏文案。
4. 中文全角标点要自然，不要机械堆砌。

## 开发检查清单

每次新增或修改前端文案时，至少检查以下项目：

1. 是否使用了统一术语。
2. 标题是否符合模板。
3. 说明是否先写状态、再写动作。
4. 按钮是否是“动词 + 对象”。
5. 表头是否用统一列名。
6. kicker 是否是短名词短语。
7. 空状态是否统一为 `当前暂无...`。
8. 文案是否符合真实后端语义。
9. 文件是否为 UTF-8 编码。

## 推荐执行方式

如果后续继续开发前端，建议按以下顺序写文案：

1. 先确定术语
2. 再确定状态词
3. 再写标题
4. 再写说明
5. 最后补按钮、表头、空状态

这样可以避免页面做到后期再大面积返工。
