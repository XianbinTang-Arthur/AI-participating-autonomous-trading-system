# Task 23 UI Information Architecture Plan

> 项目定位声明：本文件默认服从 AATS 的统一目标：在严格风控、可审计、可恢复、可治理前提下，通过自动化交易追求长期稳定盈利，为 AI 的持续自治与终身发展积累资本。详见 [项目定位声明](../../docs/project_positioning.md)。


## 目标

把当前“一个大 dashboard 承载所有职责”的结构，重构成更接近真实交易工作流的多页面控制台。

这次重构优先解决 4 个问题：

1. 交易、风控、后台管理信息混在同一层导航，认知负担过高。
2. 自动刷新时，当前页面视图会整块重绘，不利于后续做历史列表和分页。
3. 历史数据和实时数据没有分层，后续扩展会越来越臃肿。
4. 现货与合约虽然已经有文案区分，但页面结构还没有按场景彻底拆开。

## 新的信息架构

前端保留一个统一 shell，并在 shell 内拆成 6 个工作区视图：

1. `login.html`
   用于登录和会话建立。

2. `dashboard-shell.html` 中的 `overview` 视图
   作为 `/ui` 和 `/ui/overview` 的总览视图，只回答：
   - 现在能不能继续自动交易
   - 当前策略到底在做什么
   - 当前是否有持仓或在途委托
   - 当前收益和风险状态如何
   - 如果不能交易，首先要处理什么

3. `dashboard-shell.html` 中的 `strategy` 视图
   专门展示策略判断、信号拆解、目标仓位、策略门禁和风控门禁。

4. `dashboard-shell.html` 中的 `execution` 视图
   专门展示委托、成交、执行异常和卡单处理。

5. `dashboard-shell.html` 中的 `risk` 视图
   专门展示风险阻断、对账、恢复和 replay/repair 状态。

6. `dashboard-shell.html` 中的 `admin/settings` 视图
   专门展示账户、权限和运行配置，不再和交易工作台共享同一主视图。

## 布局原则

### 1. 顶部状态条固定

所有交易页面共享同一组全局状态卡：

- 运行状态
- 当前能否下单
- 交易通道
- 账户同步
- 账实核对
- 账户权益

这组信息应该在所有页面保持一致，避免用户切页后丢失系统整体上下文。

### 2. 页面按职责拆分

每个页面只保留一个主内容区域，不再把所有模块同时放入 DOM。

这样做的价值：

- 当前页面自动刷新时，只会重渲染当前页面的数据模块
- 不活跃页面不会参与本轮渲染
- 后续更容易增加分页、筛选、局部更新

### 3. 交易与管理分离

`dashboard-shell.html` 中的 `settings/admin` 工作区从交易工作流中独立出来。

原因：

- 交易员关注的是策略、委托、风险和恢复
- 后台配置属于低频管理动作，不应和实时交易信息抢同一级注意力

### 4. 现货与合约继续分场景表达

现货页面表达应偏向：

- 买入 / 卖出
- 持仓数量
- 成交金额
- 手续费

合约页面表达应偏向：

- 开仓 / 减仓 / 平仓 / 反手
- 净仓位变化
- 保证金模式
- 杠杆
- 已实现 / 未实现盈亏

## 当前这一步已完成的重构

1. 新增独立路由：
   - `/ui`
   - `/ui/overview`
   - `/ui/strategy`
   - `/ui/execution`
   - `/ui/risk`
   - `/ui/settings`

2. 前端状态管理改为从 `body[data-view]` 推断当前页面。

3. 当前页面只渲染自己的主内容容器：
   - `overviewContent`
   - `strategyContent`
   - `executionContent`
   - `riskContent`
   - `adminContent`

4. 多页面共享同一套顶部状态条、banner、会话面板、人工控制区和详情抽屉。

## 下一阶段建议

### 阶段 2：分层刷新

把自动刷新拆成 3 层：

1. 全局状态轮询
   - `/auth/session`
   - `/system/health`
   - `/system/recovery`
   - `/system/blockers`

2. 页面级实时轮询
   只在当前页面激活时拉取：
   - 最新决策
   - 最新委托
   - 最新成交
   - 最新对账

3. 历史列表层
   不再每 15 秒整表重绘，只提示“有新数据可加载”

### 阶段 3：历史页分页

优先给这些历史数据做 cursor 分页：

- 委托历史
- 成交历史
- 决策历史
- 对账历史

不建议使用传统页码分页，建议按 `timestamp + id` 倒序游标翻页。

### 阶段 4：局部更新

当前页面虽然已经拆开，但仍然会重绘当前页面整块 HTML。

后续应继续把关键区域升级为局部 patch：

- 最新状态卡
- 列表行
- 抽屉内容
- banner

## 风险控制说明

本次重构只调整前端页面结构和路由，不改变任何交易逻辑、风控规则或执行语义。

因此：

- 不影响下单行为
- 不影响权限校验
- 不影响恢复、对账、风控判断
- 只影响展示和页面组织方式
