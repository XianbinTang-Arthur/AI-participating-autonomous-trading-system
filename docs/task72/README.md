# Task72 实盘升级实施清单总览

## 1. 文档定位

本目录把“将当前系统升级成支持实盘现货 / 合约交易的系统”拆成两份可以独立执行的实施清单：

- 合约优先版独立实施清单
- 现货版独立实施清单

两份清单都只基于当前仓库状态编写，不以历史 task 文档为前置条件。

## 2. 当前执行口径

- 当前项目推荐执行路径：合约优先版
- 现货版保留为一份平行、独立、可单独启动的实施方案
- 两份清单都包含共享底座治理，不要求先完成另一份方案再启动
- 当前如果进入开发排期，应以“先完成合约优先版，再决定是否并行补现货版”为默认顺序

## 3. 共同约束

无论选择哪条路径，都必须满足以下共同约束：

- 单 runtime、单账户、单环境、单产品线部署
- 任何关键状态不确定时默认停机，而不是继续交易
- 订单、成交、余额、持仓、保证金、风险结论必须可审计
- operator 高风险动作必须具备鉴权、确认与审计留痕
- 所有新增前端与控制面文案必须使用干净的 UTF-8 中文
- 在小资金前向验证完成前，不得宣称系统具备生产级无人值守实盘能力

## 5. 使用方式

建议按以下方式使用本目录：

1. 先确定本轮只走一条主路线，不要把现货与合约的实现任务混在同一批次里推进。
2. 如果当前以真钱上线为目标，优先使用“合约优先版独立实施清单”作为主排期文档。
3. 每个阶段结束时，都要先完成本阶段验收，再进入下一阶段，不允许跳过风控、恢复、对账与停机门槛。
4. 只有在 `guarded_live` 小资金前向验证稳定后，才允许讨论更高自动化级别或更大资金量。

当前阶段 4 到阶段 6 的第三批任务已经完成第一轮实现，当前已经补齐持仓生命周期收益归因、清算距离与保证金缓冲控制面，以及资金费纳入 `trial_guard / forward validation / trial review` 的统一口径。

当前阶段 5 到阶段 7 的第四批任务也已经完成第一轮实现，当前已经补齐清算距离与保证金缓冲驱动的自动阻断 / 停机规则、`guarded_live` 启盘前自检报告，以及小资金试运行运行包的统一视图。

当前已新增第五批任务书，聚焦“自动调参二期”，当前重点是把紧急安全换档、风险预算自动收缩、执行侵略性自动收缩、持有 / 冷却节奏纳入档位，以及档位解释面板收口成一套可直接开发的任务列表。

当前 `Task73` 的阶段 1 到阶段 5 也已经完成第一轮实现，单账户并行多策略现在已具备 `strategy_sleeve_id / allocation_id / strategy bundle / sleeve pnl` 的真相链路、allocator v1、bundle recovery，以及全自动并行预算与启停控制；迁移目录已收敛到最新基线 `0001 + 0002` 两份 SQL。

## 6. 共同验收红线

以下任一项未满足，都不应进入真钱运行：

- 无法回答每一笔订单为什么允许下单、谁允许下单、最后如何成交
- 无法从系统内重建余额、持仓、保证金、手续费或资金费变化
- 无法在重启、私有 WS 中断、REST 超时、重复事件下收敛订单状态
- 对账失败后系统不会自动停机或阻断继续下单
- operator 无法通过控制面看懂当前风险状态与建议动作
- 前端或控制面存在编码污染、状态语义混乱、误导性文案

## 7. 当前建议

当前建议不是“先把现货做完再做合约”，而是直接把合约作为主路径单独收敛，因为你已经明确表示希望先做合约。

但这不意味着可以降低门槛。相反，合约路径的保证金、杠杆、风险限额、清算距离、只减仓保护、资金费对账和自动停机门槛都必须比现货更严格。
